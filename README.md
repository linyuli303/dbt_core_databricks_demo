# dbt Core + Databricks Demo

A hands-on **dbt Core** project that transforms e-commerce data in **Databricks** using a bronze → silver → gold architecture. It demonstrates source definitions, SQL transformations, snapshots, seeds, reusable Jinja macros, data-quality tests, and dbt unit tests.

## Project overview

```text
Databricks landing tables (orders, products, reviews, users - 4 tables in parquet format)
        │
        ├─► bronze_orders ──► silver_orders ────────────┐
        ├─► bronze_users ──► silver_users ──────────────┤
        ├─► bronze_reviews ─────────────────────────────┼─► gold reporting tables
        └─► products_snapshot ──► silver_products ──────┘

product_category.csv ──► seed table (separate demo; not joined into the models)
```

| Layer | Objects | What they do |
| --- | --- | --- |
| Sources | `landing.orders`, `landing.products`, `landing.reviews`, `landing.users` | Declare existing Databricks source tables. |
| Bronze | `bronze_orders`, `bronze_reviews`, `bronze_users`, `products_snapshot` | Copy raw source records; snapshot product history using `id` and `created_at`. |
| Silver | `silver_orders`, `silver_products`, `silver_users` | Standardize fields, calculate `order_amount`, expose current product records and user attributes. |
| Gold | `gold_sales__daily`, `gold_avg_rating__daily` | Aggregate revenue and review ratings for analysis. |
| Seed | `product_category` | Example category lookup loaded from CSV. |

**Gold outputs:**

- `gold_sales__daily`: total revenue grouped by order date, product, category, vendor, customer city/state, and sales channel.
- `gold_avg_rating__daily`: average rating grouped by review date and product, with the product name from the current product dimension.

## Tech stack

- dbt Core with the Databricks adapter (`dbt-databricks`)
- Databricks SQL warehouse and catalog
- SQL, Jinja, YAML, and CSV
- Packages in `packages.yml`: `dbt_utils` 1.4.1 and `dbt_expectations` 0.10.10

## Getting started

### 1. Prerequisites

- Python, dbt Core, and a compatible `dbt-databricks` adapter.
- Access to a Databricks workspace, an SQL warehouse, and a catalog where you can create schemas and tables.
- Existing `landing` schema containing `orders`, `products`, `reviews`, and `users` tables. **The source data and table-creation scripts are not included in this archive.**

Install the adapter in your Python environment:

```bash
python -m pip install dbt-databricks
```

### 2. Configure Databricks credentials

The included `profiles.yml` defines `dev` and `prod` targets. Replace the example `host`, `http_path`, and `catalog` values with your Databricks settings. Both targets read the token from the `DATABRICKS_TOKEN` environment variable—do not commit a real token.

**PowerShell:**

```powershell
$env:DATABRICKS_TOKEN = "your-databricks-token"
```

**macOS / Linux:**

```bash
export DATABRICKS_TOKEN="your-databricks-token"
```

The connection profiles use `schema: default`; the project's `generate_schema_name` macro routes configured models directly to `bronze`, `silver`, and `gold` rather than producing names such as `default_bronze`. The seed is configured for `bronze`, and the product snapshot explicitly targets `bronze`. Select or change the appropriate catalog before running against production.

### 3. Install dependencies and check the connection

Run these commands from the dbt project root:

```bash
dbt deps
dbt debug --target dev
```

### 4. Build the project

The gold models depend on `silver_products`, which reads from `products_snapshot`. Run the snapshot before building its dependent models:

```bash
dbt snapshot --target dev
dbt seed --target dev
dbt build --target dev
```

For subsequent runs after product data changes, run `dbt snapshot` again before `dbt build` to refresh the product history. To run just the transformation and tests separately:

```bash
dbt run --target dev
dbt test --target dev
```

### 5. Explore the results

```sql
SELECT * FROM gold.gold_sales__daily LIMIT 10;
SELECT * FROM gold.gold_avg_rating__daily LIMIT 10;
```

Run the queries in the **catalog configured for your chosen target**. You can also generate dbt documentation:

```bash
dbt docs generate --target dev
dbt docs serve
```

## Data quality and reusable logic

- **Source tests:** order IDs are checked for uniqueness and non-null values (configured as warnings); quantity and unit price are checked for non-negative values.
- **Gold schema test:** `dbt_expectations.expect_table_columns_to_match_set` verifies the sales output columns.
- **Unit tests:** `test_order_amount_calc` checks the calculated order amount; `test_gold_avg_rating` checks product-level daily averages.
- **Macros:** `multiply_columns_and_round` computes rounded amounts; `generate_schema_name` uses the configured schema name without the default dbt prefix. `assert_non_negative` is defined as a generic test but is **not attached to a model or column** in the provided YAML.

## Notes

- `silver_products` selects the currently valid row (`dbt_valid_to IS NULL`) from `products_snapshot`. The snapshot uses the source's `created_at` as its `updated_at` field; if products can be edited after creation, use a field that changes on every update to capture those edits reliably.
- `gold_sales__daily` groups by **date and multiple dimensions**, not just date; `gold_avg_rating__daily` groups by date and product.
- This is a demonstration project. It does not contain a scheduler, a dashboard, or the upstream ingestion pipeline.
